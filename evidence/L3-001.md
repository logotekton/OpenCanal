# L3-001 — LLM 심사 실험: 오너 평가를 재현할 수 있나

> 2026-10-07. 대상: HUMAN-001의 다리 26개 (오너 평가 = 정답). Oracle §3 L3, §10 결정(자동 검사 대신 LLM 심사).
> 근거 데이터는 로컬 임시 폴더에 있다(커밋 안 함). 이 문서에는 집계만 남긴다.

## 1. 실험

| 실험 | 심사자 | 심사자가 본 것 | 오너 평가 노출 |
|---|---|---|---|
| 보정 없음 | 맥락 없는 LLM 에이전트 3개 | 다리 26개, 커널 묶음(호스트·멤버 서브브레인), 세 축 정의("뻔하면 새로움 0", "현실 제약 고려" 포함) | 없음 |
| 보정 (2겹 교차) | 같은 방식 3개 × 2겹 | 위 + 반대쪽 절반(12~14개)의 오너 평가와 메모를 예시로 | 예시 절반만. 맞히는 쪽은 처음 본다 |

## 3. 결론

1. **보정 없는 LLM 심사는 오너와 반대로 판단한다.** 기발한 분야 간 유추(테스트 두뇌)를 높게, 현장 실무 개념(halo 커널)을 낮게 쳤다. 심사자끼리는 잘 일치하므로 우연이 아니라 체계적인 차이다. 그대로 쓰면 품질 판단을 거꾸로 이끈다.
2. **오너 예시로 보정하면 큰 기준은 재현한다.** 커널 단위 결과(halo 6~7 vs 테스트 0)가 오너와 같아졌다.
3. **다리 하나하나는 보정해도 못 맞힌다.** 축별 카파가 0 근처다. 예시 13개로는 개별 판단을 배우지 못한다.
4. **쓰임새:** L3는 다리를 거르는 관문으로 쓰지 않는다. 오너 예시로 보정한 뒤 **합성 방식이나 커널을 비교하는 델타브레인 단위 보조 지표**로만 쓴다. 표본이 작으므로(다리 26개, 평가자 1명) 평가가 쌓이면 다시 잰다.
5. **오너의 "더 창의적으로" 요청과의 관계:** LLM이 "창의적"이라 높게 치는 연결은 오너가 현실성 때문에 낮게 친 연결과 겹친다. 창의성을 높일 때는 오너 기준의 쓸모가 같이 유지되는지 사람 평가로 확인해야 한다.
