# DIRECTION — 피벗 v2 확정 (2026-07-02)

> **한 줄**: OpenCanal은 **자율 생산 personal agent 플랫폼**이다.
> 내 판단력(PAB 팩)을 심은 agent가 자는 동안 실제 산출물을 만들고, 나는 아침에 편집장으로 승인/반려한다.
> **"자는 동안 내 분신이 일하고, 아침에 실물이 와 있다."**

## 무엇이 바뀌었나

**미션은 불변**: AGI 시대에 개인의 agent가 개인을 대신한다.

v1(신뢰 네트워크)은 전제가 실패했다: ① 콜드스타트가 구조적(상대가 있어야 가치 발생, N=0) ② 마찰이 가치보다 먼저(가입→러너→페어링을 거쳐 나온 것이 "대화 초안") ③ **가치 천장이 '대화'에 묶임**(v1 로드맵 스스로의 진단).

### 기각된 프레임들 (탐색 기록 — 왜 이 방향인지의 근거)

| 프레임 | 기각 사유 |
|---|---|
| 검증장/시뮬레이터 퍼스트 | 내향적 툴링 — agent를 좋게 만드는 도구일 뿐, 그 자체로 사용자에게 주는 물건이 아님 |
| 사수 agent (판단력 전수) | 남(팀·주니어·조직)의 참여가 있어야 가치 발생 — 개인 단독으로 성립하지 않음 |
| 거울방 (자기 감사·리허설) | 결국 산출물이 말(심의·통찰) — v1과 같은 "대화 천장" 함정 |

공통 교훈: **안으로 파는 방향(검증·성찰)도, 남에게 기대는 방향(네트워크·전수)도 아니다. 밖으로, 세계에 실물을 만든다.**

## 제품 = 생산 루프 4단계

```
[Plan]              [Produce]           [Review]                [Publish]
팩 기반으로 밤의  →  산출물 생성      →  아침 승인/반려        →  승인된 것만 바깥으로
작업 큐를 스스로     (글·문서·초안·      (편집장 = 소유자,         (블로그·제출·GitHub —
결정                 제안서·코드)         반려 사유 → 팩 재ingest)   승인 게이트 통과 필수)
   ↑                                          │
   └──────── 반려가 훈련 데이터: agent가 회차마다 나다워짐 ────────┘
```

1. **Plan** — agent가 팩(decision policies + workflow playbooks + domain overlays)으로 "오늘 밤 뭘 할 가치가 있는지"를 스스로 고른다. 기회 스캔(공모·입찰·지원사업·이슈) 포함.
2. **Produce** — 실물을 만든다: 기술 문서, 블로그 글, 제출 초안, 이슈 답변, 코드. 두뇌는 실제(Claude Agent SDK headless, 소유자 구독 — v1 원칙 유지).
3. **Review** — 아침에 소유자가 승인/반려. 반려 사유는 OpenCrab 팩으로 재ingest — Correct 루프가 훈련장이 아니라 **실전 생산 중에** 돈다.
4. **Publish** — 바깥으로 나가는 모든 행동은 승인 게이트를 통과해야 한다. v1의 rigor(근거+책임 강제)가 여기서 재취업한다.

## 왜 PAB가 핵심인가 (= 왜 Moltbot/Hermes와 다른가)

기존 개인 비서 런타임은 전부 **반응형** — 시켜야 움직이고 애매하면 물어본다. 자율 생산이 안 되는 이유는 기술이 아니라 **판단**이다: 뭘 할 가치가 있는지, 어떤 톤이 나다운지, 어디서 멈춰야 하는지를 agent가 모른다. PAB 팩이 정확히 그 빈칸이다:

- **decision policies** → 작업 선택 (뭘 할지)
- **red flags** → 금지선 (뭘 하지 말지)
- **communication style** → 산출물의 나다움
- **workflow playbooks / domain overlays** → 실행 방법과 도메인 지식

**PAB는 자율성의 면허증이다.** 판단력 없는 자율은 위험하고, 판단력 있는 반응형은 아깝다.

## 본질 (한 층 아래의 정의)

만드는 것은 워크플로우가 아니라 **일꾼** — 나의 판단력을 탑재한, 실행 가능한 나의 사본이다.
- **팩 = 사본의 정신** (decision policies·red flags·style·playbooks — PAB가 증류한 판단 기준)
- **agent 런타임 = 사본의 몸** (그 기준으로 읽고·고르고·만들고·멈추는 실행체)
- **아침 리뷰 = 수렴 장치** (틀릴 때마다 나에게 배워 매일 더 나에 가까워지는 메커니즘)

밤새 생산은 본질이 아니라 **사본의 첫 직업** — 능력이 아니라 판단이 병목인 일이라 사본이 증명되는 무대다. 누가 루프를 통째로 베껴도 뺏기지 않는 것: 수백 번의 반려·교정으로 축적된 팩. 그것이 자산이다.

```
점수판:  돈        — "이번 달 벌어온 금액" (P1~P2 조준점 — 첫 수익 이벤트 마일스톤)
표면:    스펙터클  — 아침 리뷰 = 밤사이 일지 (P0부터 — retention + 공유 = 배포 채널)
기반:    공장      — Plan→Produce→Review→Publish (생산 루프)
본질:    사본      — 팩 + 런타임 + 수렴 장치 (축적되는 자산)
```

## 원칙

- **산출물은 실물이다.** 대화·통찰·리포트가 아니라, 내가 안 만들었는데 존재하는 것. 가치 천장 탈출.
- **N=1 첫날 가치.** 산출물의 소비자는 이미 존재하는 바깥 세계(독자·주최측·GitHub). 다른 사용자도 상대 agent도 필요 없다.
- **바깥으로 나가는 모든 것은 승인 뒤에.** 자동 발행 금지. 승인 게이트는 병목이 아니라 신뢰의 원천.
- **반려가 훈련 데이터.** 아침 리뷰가 곧 팩 갱신 — 별도의 훈련 단계를 만들지 않는다.
- **모든 판단에 출처가 남는다 (provenance).** 일지의 각 판단은 정책 id를 인용한다 — 반려 교정이 감이 아니라 정확한 정책을 겨냥하게. 갱신된 팩은 evaluation cases로 회귀 검증한다.
- **진화는 두 트랙.** 정신(판단·팩)은 **나다움에 수렴** — 갱신은 소유자 승인을 거치고 버전이 남는다 (승인율·돈을 정신의 목적함수로 삼으면 아첨꾼/타인이 된다). 기술(플레이북·커넥터·요령)은 **성과에 수렴** — 자유롭게 진화한다.
- **배포는 열고, 진화는 독점한다 (MCP 소켓).** 팩은 콘센트(MCP)로 어떤 외부 워크플로우에든 꽂힌다 — `pack_query`(판단 읽기) + `report_outcome`(결과 피드백). 읽기는 학습이 아니다: 밖에서 많이 쓰일수록 교정·버전관리가 일어나는 홈그라운드의 가치가 커진다. 워크플로우 생성 플랫폼은 만들지 않는다 — 분신 안에서는 판단이 일의 구조를 즉석에서 만들고, 분신 밖에서는 남의 플랫폼(n8n 등)에 꽂힌다.

## 하지 말 것 (anti-direction)

- 네트워크·검증 딱지·평판 부활 금지 (지금은. 산출물 실적이 쌓이면 그것이 평판의 원천이 된다).
- 범용 반응형 비서 경쟁 금지 (v1 anti-roadmap 유지 — 채널 수·skill 수는 그들의 게임).
- 자동결제·완전자율 대외 행동 금지선 유지.
- 승인 없이 소유자 이름으로 발행 금지.

## 성공 기준 (north star)

- **아침 승인율**: 밤새 만든 산출물 중 소유자가 승인한 비율 (판단력 적중).
- **수렴**: 같은 사유의 반려가 회차마다 감소하는가 (agent가 배우는가).
- **실물 수**: "내가 안 만들었는데 이번 주에 세상에 존재하게 된 것"의 개수 — 궁극의 지표.

## 단계

- **P0 — 밤 1회전 (최소 증명)**: 소유자 팩 1개 로드 → 작업 1개(예: BIMGraph 문서 or 기술 블로그 글) 자율 생산 → 아침 리뷰(승인/반려+사유) → 반려 재ingest → 재생산에서 행동이 달라짐을 확인.
  - 구현 형태: NightPolicy/NightTask/NightRun/NightArtifact 원장(packages/db) + night 프로토콜(packages/shared/night.ts) + `opencanal-runner night run`(밤 실행기) + `/night` 아침 리뷰 + `/night/plan` 정책·지시 편집(apps/web) + MCP 소켓(apps/socket — pack_query/report_outcome).
- **P1 — Plan 자동화 + 돈 조준**: 작업 큐를 agent가 스스로 계획(기회 스캔: 공모·입찰·이슈·마감), 다중 산출물, 밤 스케줄러. Plan의 선택 정책이 "돈과 가까운 작업 우선"으로 기운다.
- **P2 — Publish 커넥터 + 첫 수익 이벤트**: 승인 게이트 뒤의 실제 발행(블로그/GitHub/제출 패키지). 텔레그램 브리지를 아침 승인 채널로 재활용. 마일스톤: 첫 수익 이벤트(공모 선정 1건 또는 자산 판매 1건).
- **P3 — 지표 + 개방**: 승인율/수렴/실물/수익 대시보드. (선택) 다른 사용자에게 개방 — 산출물 실적이 쌓인 agent들 사이에서 v1의 네트워크·평판이 비로소 의미를 갖는지 재검토.

## 기각된 아이디어 추가 기록 (탐색 계속의 근거)

- **워크플로우 생성 플랫폼**: 분신의 요점은 일의 구조가 판단에서 나오는 것 — 에디터를 만드는 순간 자동화 패러다임(사람이 구조를 짬)을 재수입한다. 외부 워크플로우는 BYO(남의 플랫폼에 MCP 소켓으로 꽂기).
- **"팩만 있으면 된다" (플랫폼 무용론)**: 끼워넣은 팩은 거부권만 있고 발의권이 없다. 읽기는 학습이 아니다 — 어느 정책이 오발했는지 추적(provenance)과 교정·회귀검증이 없으면 팩은 정지 화상으로 부패한다. 팩=소스코드, 플랫폼=런타임+git+CI.

리브랜딩(레포 rename)은 방향이 코드로 굳은 뒤에 한다.
