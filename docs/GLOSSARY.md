# 용어집 — opencanal

> 상태: **확정** (2026-10-06). 코드, MCP 도구 이름, 스키마에 그대로 쓴다. 한 개념에는 한 이름만 쓴다.

## 표기 원칙

- **커널**은 canal(운하)이다. opencanal의 한글명이 오픈커널이다.
- 운영체제의 kernel과 헷갈리지 않도록 영문은 항상 **canal**로 쓴다.
- 비유 체계는 **두뇌(brain)** 쪽과 **운하(canal)** 쪽 두 갈래다.

## 핵심 용어

| 한글 | 영문 (코드) | 정의 | 비고 |
|---|---|---|---|
| 두뇌 | `Brain` | 한 사용자의 secondbrain 전체. Obsidian 볼트, OpenCrab 팩 등 | **플랫폼에 올라오지 않는다.** 사용자 쪽에만 있다 |
| 서브브레인 | `Subbrain` | 두뇌에서 골라낸 노드·엣지 묶음. 플랫폼에 공개하는 단위 | 버전마다 불변 |
| 서브브레인 버전 | `SubbrainVersion` | 서브브레인을 공개한 한 시점의 고정본 | 수정하면 새 버전. 델타브레인은 특정 버전을 인용한다 |
| 호스트 서브브레인 | `host subbrain` | 커널을 연 사람이 자기 쪽으로 내놓은 서브브레인 | "내 두뇌에 달려든다"에서 '내 두뇌' 자리. 다른 참여자에게도 보인다 (대칭 동의) |
| 질의 | `Query` | 커널을 여는 키워드나 과제. 예: "내 두뇌 평가해줘", "마케팅 전략 구상" | |
| 커널 | `Canal` | 질의 하나로 열리는 연결 세션. 호스트 서브브레인 1개와 매칭된 남의 서브브레인 N개로 이뤄진다 | |
| 커널링 | `canaling` | 커널을 열어서 서브브레인들을 연결하는 행위 | |
| 합성기 | `Synthesizer` | 커널 안의 서브브레인들을 읽고 델타브레인을 만드는 주체 (LLM) | v0은 질의자의 LLM이 맡는다 |
| 델타브레인 | `Deltabrain` | 커널이 남기는 결과 지식그래프. 참여자 전원이 받는 산출물 | 대화 로그가 아니다 |
| 창발 노드·엣지 | `emergent` | 델타브레인에서 **서로 다른 주인의 서브브레인을 잇는** 새 노드·엣지 | 창발을 측정하는 단위 |
| 출처 | `provenance` | 델타브레인의 노드·엣지가 어느 서브브레인 버전의 어느 노드에서 나왔는지 남긴 기록 | 기여자 표시와 향후 과금의 근거 |
| 공개 / 비공개 | `public` / `private` | 서브브레인의 두 상태. 가져온 직후는 비공개다. 공개여야 검색과 커널에 나온다 | 사용자에게 "삭제"는 없다. 서버는 모든 버전을 보관한다 |
| 비공개 기여자 | `private contributor` | 지금은 비공개인 서브브레인의 주인이 기존 델타브레인에 남긴 기여. 주인 표시는 암호화한다 | |
| 티어 | `Tier` | 요금 등급. 노출되는 MCP 도구와 한도를 정한다 | 기능을 완성한 뒤 세분화 |

## 쓰지 않는 말

| 피하는 말 | 이유 | 대신 |
|---|---|---|
| 스냅샷 | 두뇌 전체 백업으로 오해하기 쉽다 | 서브브레인 / 서브브레인 버전 |
| 팩 | OpenCrab 팩과 섞인다 | 서브브레인 (가져오기 원본을 말할 때만 "OpenCrab 팩") |
| 합류 그래프, 결과 그래프 | 이전 초안에서 쓴 이름이다 | 델타브레인 |
| 대화, 채팅 | 결과물은 대화 로그가 아니다 | 커널, 델타브레인 |
| 삭제, 철회 | 실제로 지우지 않는다. 사용자를 오도한다 | 비공개 |
| kernel (영문) | OS 커널과 섞인다 | canal |
