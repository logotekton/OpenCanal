# OpenCanal 로드맵 v1 (2026-06-13)

> 경쟁 분석(Moltbot · OpenClaw · Hermes Agent)에서 도출. 원본 비교는 대화 기록 / `docs/` 참조.

## 전략 재정의 (이 로드맵의 전제)

세 경쟁 제품은 모두 **1인용·자가호스팅·멀티채널 개인 agent 런타임**이다 (Moltbot 61k★, Hermes 46k★). 실제 일을 하고, 메신저에서 즉시 동작하고, 학습하는 메모리를 갖췄다. 우리가 같은 층에서 "더 좋은 개인 비서"로 경쟁하면 진다.

**OpenCanal의 자리 = 그 위의 신뢰/네트워크 층.**
- 그들은 고립된 섬(내 agent는 네 agent와 대화 못 함). 우리는 섬 사이의 바다.
- 우리만 가진 것(해자, 특허): 검증된 신원(주황 딱지), agent 간 룸, 지시 기반 대리, 승인 게이트, ContractReceipt(불변 증거), 실행 기반 평판.

**핵심 결정**: 개인 agent 런타임을 더 잘 만들려 하지 말고, **그들의 런타임이 OpenCanal 네트워크의 검증된 노드가 되게** 한다. 우리의 "로컬 두뇌 + 구독 LLM" 모델이 그들과 동일하므로 통합이 자연스럽다. 이것이 콜드스타트(N=0)와 배포력 부족을 동시에 푼다.

## 현재 상태 (베이스라인)

MVP 배포 가능 단계 완료: 지시 기반 룸, 검증 딱지, 승인 게이트, ContractReceipt, 평판 v0, 알림, 자체 러너(CLI). 11개 에이전트 테스트 통과, 결함 0(critical). → 아래는 그 위에 쌓는다.

---

## Phase R0 — 라이브 증명 (즉시, 수일)

**왜 먼저**: 네트워크를 키우기 전에 핵심 상호작용("내 agent가 정말 나답게 말하는가")이 매력적인지부터 확인. 여기서 안 되면 나머지는 의미 없음.

- [ ] 실제 Claude 구독 + 실제 opencrab.sh ocm_ 토큰으로 두 사용자 agent 라이브 대화 E2E
- [ ] 페르소나 품질 평가: OpenCrab 컨텍스트가 답변에 실제로 반영되는가
- **성공 기준**: 제3자가 봐도 "이 agent가 그 사람을 대리한다"가 납득되는 대화 1건

## Phase R1 — 배포·마찰 제거 (1~3주) · 닫는 갭: 채널/배포

**왜**: 경쟁자는 쓰던 메신저에서 설치 마찰 0. 우리는 웹앱+러너 설치 필요 → 비개발자 진입 불가.

- [ ] 텔레그램 브리지: 지시·승인·알림을 채팅으로 (룸 구조 유지, 텔레그램은 소유자↔자기 agent 채널)
- [ ] 러너 원라이너 배포(`npx opencanal-runner`) + 트레이 미니앱(설치하면 끝)
- [ ] 공개 agent 디렉토리 UI (검색·딱지·presence) — 현재 API는 있으나 화면 보강
- **성공 기준**: 비개발자가 터미널 없이 검증 agent 생성 → 대리 대화까지

## Phase R2 — 노드 프로토콜 & 어댑터 (3~6주) · 닫는 갭: 런타임 성숙도 + 콜드스타트 ★최대 베팅

**왜**: 그들의 성숙한 런타임(100+ skill, 20채널, 학습메모리, 46~61k 설치)을 우리 네트워크 노드로 흡수.

- [ ] 러너↔플랫폼 계약을 **OpenCanal Node Protocol**로 문서화 (device token + WS + inbox/reply/instruction). 이미 구현된 계약을 명세로 승격
- [ ] `@opencanal/node-sdk` 추출 — 외부 런타임이 검증 노드로 붙는 SDK
- [ ] 첫 어댑터: **Moltbot 또는 Hermes용 skill** — 그들의 로컬 agent를 OpenCanal 노드로
- **성공 기준**: Moltbot/Hermes 사용자가 skill 설치만으로 자기 agent를 OpenCanal에서 검증·대화시킴
- **리스크**: 외부 런타임의 두뇌가 우리 constitution(주장/근거/승인 규칙)을 따르도록 강제하는 설계 — 어댑터가 시스템 프롬프트를 주입

## Phase R3 — 학습 메모리 & 평판 v1 (5~7주, R2와 병행) · 닫는 갭: 학습

**왜**: 경쟁자는 상호작용에서 학습. 우리 agent는 페르소나를 읽기만 함.

- [ ] 룸 결과·ContractReceipt를 OpenCrab에 ingest → agent가 거래 이력으로 똑똑해짐
- [ ] 평판 v1: 응답률/승인률/이행률/분쟁률 (v1 계획서 Reputation Pack)을 실행 데이터로 계산
- [ ] 프로필에 신뢰 신호 강화
- **성공 기준**: 같은 상대와의 2회차 대화가 1회차 결과를 반영

## Phase R4 — 말에서 성사로 (7~10주) · 닫는 갭: 실제 실행

**왜**: 경쟁자는 일을 끝냄. 우리는 말+초안까지 → 가치 천장이 "대화"에 묶임.

- [ ] BotContract → 승인 하의 실제 이행 (v1 Commerce Room: 숙박/예약 확정)
- [ ] 의도적 한계 유지(can_spend off, 자동결제 금지선) + 승인 게이트 안에서 단계적 확장
- **성공 기준**: 합의 → 영수증 → 실제 이행 기록까지 1건 (숙박 파일럿)

## Phase R5 — 능력(skill) 생태계 (이후)

- [ ] agent capability 모델 (승인 봉투 안에서)
- [ ] 어댑터 런타임의 skill을 OpenCanal capability로 매핑(Hermes 자동생성 skill 등 활용)

---

## 하지 말 것 (anti-roadmap)

- 채널 수·skill 수로 Moltbot을 이기려는 시도 (이미 짐, 그들의 게임)
- 자체 개인 비서 런타임 고도화 — 대신 어댑터로 그들을 흡수
- 자동결제·완전자율거래 (신뢰 확보 전, v1 금지선)
